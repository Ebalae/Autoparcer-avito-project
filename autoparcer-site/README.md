# Autoparcer website

Отдельный веб-проект для регистрации пользователей и оформления доступа к приложению. Сайт использует встроенный Node.js HTTP-сервер и SQLite; внешние npm-пакеты не нужны.

Для регистрации и входа используется логин, а не адрес электронной почты. Новые логины могут содержать от 3 до 32 букв латинского или русского алфавита, цифр, точек, дефисов или подчёркиваний. Старые аккаунты сохраняют возможность входа по прежнему адресу почты, который становится их логином. В `/profile.html` пользователь может управлять подпиской и сменить пароль, подтвердив текущий.

После регистрации или входа пользователь переходит в `/profile.html`: там отображается статус подписки и доступны месячный и годовой тарифы. Скачать версию для Windows можно с главной страницы или из профиля после входа и при активной подписке.

## Панель администратора

Панель доступна только по отдельному секретному адресу из `ADMIN_PATH` и после входа в аккаунт, указанный в `ADMIN_USERNAMES`. Сначала зарегистрируйте аккаунт владельца, затем укажите уже зарегистрированный логин в `.env` — например, `ADMIN_USERNAMES=owner,second-admin` — и перезапустите сервер. После настройки логин из `ADMIN_USERNAMES` нельзя зарегистрировать, что предотвращает захват ещё не созданного администраторского аккаунта. Задайте `ADMIN_PATH` как `/` и случайную строку из 32–128 символов; например, сгенерируйте значение командой `node -e "console.log('/' + require('node:crypto').randomBytes(32).toString('hex'))"`. Не используйте секреты из старых или опубликованных примеров. Без обеих переменных панель не открывается; стандартные адреса `/admin` и `/admin.html` не используются.

В панели можно искать аккаунты, выдавать подписку на 30, 90 или 365 дней (срок добавляется после текущей активной подписки), отзывать доступ и удалять аккаунты. Удаление завершает все сеансы и удаляет данные аккаунта; связанные записи платежей сохраняются без привязки к пользователю. Администраторские аккаунты защищены от удаления через панель.

## Публикация установщика

Загрузите Windows-установщик на VPS вне каталога `public`, чтобы файл нельзя было скачать по прямой публичной ссылке. Укажите его полный путь в `.env` через `APP_DOWNLOAD_PATH`, например `APP_DOWNLOAD_PATH=/opt/autoparcer/app/Autoparcer-Setup-1.0.2.exe`, и убедитесь, что пользователь службы Node.js может читать файл. Маршрут `/download` выдаёт установщик только вошедшим пользователям с активной подпиской. После изменения `.env` перезапустите службу сайта.

## Требования

- Node.js 22.13 или новее.

## Локальный запуск

1. В этой папке скопируйте `.env.example` в `.env`.
2. Оставьте для локального запуска `PUBLIC_ORIGIN=http://localhost:4175`.
3. Запустите `npm start`.
4. Откройте `http://localhost:4175`.

Аккаунты и платежи хранятся в `data/autoparcer.sqlite`. Пароли сохраняются как хеши scrypt с уникальной солью; браузер получает только случайную HttpOnly-сессию. База и секреты не включаются в папку сайта для публикации.

## Подключение ЮKassa

1. Создайте магазин и получите `shop id` и секретный ключ в личном кабинете ЮKassa.
2. Укажите в `.env` публичный HTTPS-адрес сайта как `PUBLIC_ORIGIN`, а также `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`.
3. В настройках уведомлений магазина укажите `https://ваш-домен/api/yookassa/webhook` и событие `payment.succeeded`.
4. Проверьте тестовый платёж в тестовом режиме ЮKassa, затем переключите магазин в рабочий режим.

Цена месячного тарифа задаётся через `SUBSCRIPTION_PRICE_RUB` (по умолчанию 990 ₽ за 30 дней). Профиль предлагает месячный период и 12 календарных месяцев со скидкой 30% от стоимости двенадцати месячных периодов; годовая цена пересчитывается автоматически. Оплата разовая, без автоматических списаний. При оплате пользователь указывает email для фискального чека; сайт передаёт его ЮKassa и не сохраняет в базе аккаунтов. Платёжный запрос содержит чек с предметом расчёта «услуга», полной предоплатой и кодом НДС `1` («Без НДС»), выбранным оператором для кассы. Сервер сохраняет выбранный тариф и сверяет платёж запросом к API ЮKassa, а затем продлевает доступ на соответствующий срок.

Правовые документы доступны на `/privacy.html` и `/terms.html`; версии документов и время отдельных согласий сохраняются при регистрации. Эти файлы содержат шаблонные реквизиты и не подходят для production без заполнения сведений об операторе, контактного адреса, версии и даты вступления документов в силу. Перед публичным запуском проверьте фактического поставщика хостинга и содержание документов с профильным юристом. Также разместите актуальный установщик, настройте HTTPS и резервное копирование базы, предусмотрите восстановление доступа при утере пароля. Для защищённой раздачи установщика с VPS задайте `APP_DOWNLOAD_PATH` на локальный файл, доступный процессу Node.js; маршрут `/download` выдаст его только после проверки входа и активной подписки. Внешнюю HTTPS-ссылку можно задать через `APP_DOWNLOAD_URL`, но файл по ней может быть скачан напрямую теми, кто получил ссылку. Electron-клиент входит через `/api/app/login`, запрашивает актуальный статус через `/api/app/me` и завершает токен через `/api/app/logout`; мониторинг запускается только с активной подпиской и останавливается после её истечения. Старые установленные версии до обновления клиента эту проверку не выполняют.

На один аккаунт допускается один активный сеанс Electron-приложения. Вход в приложении на другом компьютере отзывает предыдущий сеанс; работающий клиент обнаруживает это при ближайшей проверке и останавливает мониторинг. После включения ограничения существующим пользователям потребуется заново войти в приложение. Сеансы входа на сайте не ограничиваются.

Мониторинг выполняется на компьютере пользователя: приложение и компьютер должны быть включены. Покупка подписки на сайте сама по себе не запускает круглосуточный облачный мониторинг.

## Переменные окружения

Скопируйте `.env.example` в `.env`. Не публикуйте `.env`, секретный ключ ЮKassa или файл SQLite. В production задайте `NODE_ENV=production`, публичный HTTPS `PUBLIC_ORIGIN`, путь к базе в постоянном хранилище через `DB_PATH`, логин владельца в `ADMIN_USERNAMES` и путь к локальному установщику через `APP_DOWNLOAD_PATH` (или внешнюю HTTPS-ссылку через `APP_DOWNLOAD_URL`). Устанавливайте `TRUST_PROXY=true`, только если перед Node.js настроен доверенный reverse proxy, перезаписывающий `X-Forwarded-For`.
